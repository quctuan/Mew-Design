Core Concept

Concept & Value Proposition

Giải pháp xóa bỏ tình trạng Data Fragmentation giữa luồng Research và Design.

Problem Statement: Quá trình R&D tính năng mới thường gặp rào cản Bottleneck do Context bị phân tán: Raw Input nằm trên Jira, Tài liệu Research định cư biệt lập, và UI/UX Specs rải rác trên Figma.

Nền tảng Master Flow Design đóng vai trò như bản thể Orchestrator trung tâm:

  • Single Point of Contact: Khởi chạy vòng đời thiết kế (Design Lifecycle) phân tán chỉ bằng một Command Line hợp nhất.
  • Data Continuity: Dòng chảy thông tin đi từ Raw Data -> UX Insights -> Build Specs mà không bị đứt gãy Context (Single Source of Truth).
  • Format Standardization: Đảm bảo tính nhất quán tuyệt đối về cấu trúc Output (Docs, URD, Specs) trên diện rộng Framework dự án.

System Architecture

2-Phase Routing Architecture

Core Principle: Phân nhánh tiếp nhận Input Data và hội tụ tại Publishing Layer cuối cùng.

PHASE 1: INPUT ROUTING

Tầng Routing & Custom Processing

Hệ thống kích hoạt AI nhận diện Tác vụ, phân tách thành Hệ Multi-Agent Sub-workflows tương ứng với bản chất Data Source. Ở tầng này, các Agent thực thi việc R&D (Nghiên cứu & Thiết kế) một cách độc lập cho tới khi sinh ra Đặc tả Kỹ thuật dạng Markdown Specs.

1. Jira Integration

Đồng bộ tự động thông tin Issue có sẵn.

2. Unstructured Email/Text

Hỏi đáp tương tác bóc tách yêu cầu hỗn loạn.

3. Khởi tạo Insight Mới (BAU/SIP)

Thực thi khảo sát thị trường định lượng.

PHASE 2: OUTPUT STANDARDIZATION

Tầng Publishing & Integration Layer

Bất chấp bản chất Input, mọi Data Pipeline trên đều hội tụ về một chốt chặn Post-Processing ngầm định. Giai đoạn này đảm bảo tài liệu được trình bày chuẩn hóa cho các bên Stakeholders tiêu thụ.

Core Routing [2/3]

Phân tích Yêu cầu Tự Do (Unstructured Text)

Xử lý các thông tin phi cấu trúc tiếp nhận từ Khách hàng, Đối tác qua môi trường Email/Chat.

Mô hình Tương tác Năng động (Interactive NLP)

Do bản chất thông tin phi cấu trúc thiếu Context Keys như hệ thống Task Manager, luồng này thay thế API Fetch bằng quy trình Conversational Fetching để trực tiếp bóc tách dữ liệu từ Input của Operator.

01

Recursive Prompting

Hệ thống switch sang trạng thái chờ, khởi tạo các touch-points yêu cầu bổ sung Multi-modal Input (Text, Attachments) theo kịch bản định hướng.

02

Data Cleansing Engine

Khởi tạo NLP Pipeline loại trừ các cấu trúc giao tiếp thứ cấp (Salutations, Signatures, Forward threads) nhằm cô đọng ra Requirement Vector cốt lõi.

03

P&G Innovation Framework

Ngăn xếp phân tích bối cảnh áp dụng khuôn mẫu thiết kế Goosebumps Strategy, đề xuất Concept Giải pháp mang định hướng nâng cấp thay vì thụ động vá lỗi (Patching).

04

Technical Documentation Translation

Biên dịch Concept được rà soát thành Hồ sơ Đặc tả (URD) bao gồm cả UI Copywriting, Logic States chuẩn bị cho giai đoạn Handoff sang Front-end.

Governance Policy

Operation & Checklist (Best Practices)

Duy trì khung tiêu chuẩn về Môi trường Human-In-The-Loop (HITL).

Chất lượng Thông số (Prompt Metadata)

Garbage In - Garbage Out. Nền tảng phân tích Yêu cầu dựa vào các Ngữ cảnh Khởi nguyên (Contexts). Cung cấp các lệnh điều khiển mơ hồ (Vd: "Sửa nút Trang Chủ") sẽ dẫn đến Output phi chuẩn. Buộc phải thiết lập rõ ràng Mục tiêu Kinh doanh (Why), Kỳ vọng Trải nghiệm (How).

Quyền phê duyệt Phủ quyết (Reject Autonomy)

Luồng Design Flow được thiết kế với chốt xả HITL (Human-in-the-loop) thường xuyên. PO/UIUX bắt buộc phải từ chối (Reject) hoặc điều chuyển định hướng bằng Override Contexts nếu Kiến trúc Giải pháp ban đầu định hình sai lệch so với Core Product Vision.

Rủi ro Đứt gãy Post-Processing

Tuyệt đối không bỏ qua giao thức "Khai báo UID Code" ở Phase 2. Mọi sự đứt gãy tại Workflow Component này sẽ làm suy sập toàn bộ Cấu trúc Tự động hóa ở hai tầng cuối (Auto-Map Design Screenshots & Data Tracker Exports).
