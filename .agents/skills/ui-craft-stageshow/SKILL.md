# UI craft with Stageshow

For every task that creates or changes visible UI, load this skill alongside the existing implementation workflow. Read ../stageshow/references/craft.md and the relevant sections of ../stageshow/references/motion.md. State which mode applies. Do not launch an unrelated redesign for backend-only tasks.

## Route by deliverable

- **Real app, dashboard, website, or editable Figma screens:** use craft principles for hierarchy, spacing, alignment, legible type, meaningful content, cause-and-effect motion and responsive layouts. The existing web/Figma workflow owns construction and verification. Keep working controls, business rules, error/loading/empty states, accessibility and real content. Do not introduce filler bars, cursor theatre, cropping, fixed story timing, or simulated success into a functional product. Do not require filming a gold example for ordinary UI edits.
- **Illustrative hero, feature card, scripted showcase, or cursor walkthrough:** read ../stageshow/SKILL.md and follow its full staging, gold-reference, motion and rehearsal workflow. Keep the authored scene separate from functional app state. Respect upstream licenses and product marks.
- **Mixed page:** apply full staging only to the illustrative region; use the production mode elsewhere.

## Ownership and precedence

User brief and approved reference → project design system/components/tokens → existing implementation/tool workflow → Stageshow craft. Reuse library instances and code components; do not create a parallel component kit or global CSS reset. Stageshow theme defaults, simplified copy, timing and framing are illustration defaults, not overrides for product UI. Glass is used only where the brief calls for it.

Figma tools retain their prerequisites and binding audits. Existing render/critique routines own UI QA; motion, Lottie and deployment skills retain their own responsibilities. Do not duplicate a review loop or add publication approvals. No tool call, install, deployment, subagent, or shared-library edit is authorized by merely loading this skill.

## Finish

Check the actual output at desktop and narrow widths, text fit, focus/keyboard operation and reduced motion where relevant. Verify real interactions in production mode; rehearse every beat and loop seam in illustration mode. Report checks actually performed and limitations; never claim a film/gate passed without its successful output. Keep project tokens and component reuse intact.
