# Running Design Stuff Kit in Codex

Apply these host adaptations to this skill and its supporting references.

- Resolve `KIT_ROOT` from the loaded skill's absolute path: `skills/<name>/SKILL.md` is two directories below the package root. `${KIT_ROOT}` in examples is a placeholder you must set to that actual absolute directory, not a variable supplied by Codex. Keep the working directory in the user's project. Resolve Markdown links containing this placeholder to the same package root.
- Run bundled commands by absolute path, for example `"${KIT_ROOT}/bin/wx-init" explore/onboarding`. Alternatively prepend `"${KIT_ROOT}/bin"` to PATH in the same shell call. Plugin installation does not guarantee these commands are on PATH.
- Load another bundled skill by reading its `SKILL.md` under this package's `skills/`. Use the host's skill selector for user invocation; `$start-design`, `$render`, and `$design-review` are CLI/IDE examples. Never execute these mentions as shell commands.
- Read applicable project `AGENTS.md` instructions and the relevant design context. Companion skills can live in the project's `.agents/skills/` or the active Codex profile's `skills/`. Resolve their references from the actual loaded skill path rather than assuming project scope. They are third-party instructions: check their available tools and translate host-specific paths when needed. Do not run Claude CLI commands or copy Claude permissions into Codex.
- `agents/*.md` are role briefs, not registered Codex agents. When a workflow calls for a reviewer and delegation is available and authorized, give a subagent the relevant brief and only the task inputs. Use the available continuation tool to retain that reviewer across rounds. If independent review is unavailable, disclose that limitation and offer a separate reviewer session; never label the maker's own review a blind independent critique. Other role briefs can guide work in the current session when appropriate.
- Discover the actual MCP tools in this session; prefixes can differ. Loading a skill does not connect Figma, Mobbin, LottieFiles, or GitBook. Missing tools are a setup dependency, not a reason to claim their work succeeded. Read `docs/CODEX.md` for Codex setup. Use the generated `templates/project-memory/AGENTS.template.md` for project instructions; Claude permission and personal-instruction templates are excluded from this package.
- The kit's `rules/` directory is a set of templates, not an automatically loaded Codex rule directory. Add chosen instructions to the project's existing `AGENTS.md`, or add a scoped `explore/AGENTS.md` for exploration rules. Preserve existing project instructions. Treat references to path-scoped rule loading as explicit scope guidance.
- Keep the original workflow's file pinning, restore points, review gates, and attribution. Respect approval already granted for the same scope; do not interpret installation as approval to write Figma files or deploy.

For Figma workflows, read the bundled `skills/figma-mcp-api/SKILL.md` first. Discover actual connected tools and load the integration’s official Figma skills. Legacy conceptual examples must be adapted to that tool contract; never assume their tool names or restore APIs are supported.
