# Explore versus final

When the designer requests alternatives, experiments, or options that may be discarded, use the `explore-vs-final` skill if it is installed. Build for comparison and iteration: direct positioning and local values are fine, because auto layout and token binding are costs paid for work that lasts.

Explore mode relaxes construction, not standards. It never permits writes to a shared design-system library, it does not skip loading the track's skills (they carry the traps and component references), and it does not lower content detail: copy and structure stay real.

When a direction is selected for implementation, convert only that direction into maintainable layout, appropriate token bindings, reusable components, and complete states. Leave rejected options raw as exploration history. Record intentional exceptions. If the decision stage is unclear and would change how the canvas is built, ask whether the result is for comparison or handoff: guessing "raw" wrongly costs a rebuild, but guessing "final" wrongly lets a structure without auto layout slip into handoff.
